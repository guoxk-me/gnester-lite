# Internationalization / 国际化

## Mental model

- Nest-managed HTTP JSON routes negotiate language through `Accept-Language`.
  Supported base languages are `en` and `zh`; region tags, weighted ranges, and
  wildcards are accepted, for example `zh-CN, zh;q=0.9, en;q=0.8`. The fallback
  is `en`.
- Success and failure share the JSON envelope
  `{ code, message, data, errors }`. `code` always matches the HTTP status;
  success payloads are placed in `data`, while failures use `data: null`.
- `message` and validation `errors[].reason` are localized. Clients must branch
  on `code` and stable business fields, never translated text.
- Catalog-backed business errors retain localized detail. An uncatalogued
  literal keeps its detail in English and falls back to the localized HTTP
  status message for other languages, preventing mixed-language responses.
- Localized HTTP responses expose `Content-Language` and
  `Vary: Accept-Language` so shared caches keep representations separate.
- `HttpResponseModule` registers the envelope interceptor/filter.
  `I18nCatalogModule` loads translation JSON for any consumer that needs
  `I18nService` without HTTP wrapping side effects.

Example:

```json
{
  "code": 200,
  "message": "成功",
  "data": { "id": 1 },
  "errors": null
}
```

## Key files

- `src/infra/i18n/` — language resolution, catalog module and locales
- `src/infra/http/` — response module, envelope interceptor and exception filter
- `src/common/http/api-envelope.types.ts` — framework-free envelope contracts
- `src/bootstrap/http/validation.pipe.ts` — validation details inside the envelope
- `src/bootstrap/http/openapi.config.ts` — envelope schemas and the global
  `Accept-Language` parameter in development OpenAPI
- `nest-cli.json` — copies `infra/i18n/locales/**/*` into `dist`

## Wire-contract boundaries

- Terminus health probes use `@SkipApiEnvelope()` and keep their native probe
  body on both success and failure. Operators must not parse them as an API
  envelope.
- SSE handlers returning `Observable<MessageEvent>` and `StreamableFile`
  download bodies bypass the envelope automatically because they are streams;
  JSON failures raised by a download operation still use the envelope.
- A `204 No Content` response has no wire body, even though other responses on
  the same operation (for example a `404`) use the envelope.
- `/api/session` and its login, refresh, and logout routes are Nest application
  controllers. JSON success and failure responses use the shared localized
  envelope.
- Future Socket.IO consumers own their event payloads; the HTTP envelope and headers do not apply to frames. No teaching gateway or AsyncAPI catalog is shipped.

Use `@SkipApiEnvelope()` only for an additional Nest HTTP route whose native
wire contract must remain intact. OpenAPI must document that route in the same
raw form.

## Adding copy

1. Add keys under `src/infra/i18n/locales/{en,zh}/`.
2. Keep both language catalogs key-compatible; the build artifact gate requires
   every catalog file in production output.
3. Translate catalog-backed business failures with an explicit `messageKey`
   and optional `messageArgs`. Legacy `errors.*` exception messages are also
   recognized; arbitrary dotted strings are treated as literal messages.
